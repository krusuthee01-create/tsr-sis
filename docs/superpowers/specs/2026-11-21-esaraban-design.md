# ระบบสารบรรณอิเล็กทรอนิกส์ (e-Saraban) — เอกสารออกแบบ

สรุปจากการสัมภาษณ์ออกแบบ (grill-me) วันที่ 21 พ.ย. 2569 ตัดสินใจครบ 26 ข้อ
แทนระบบเดิมบน Google Apps Script (`Code.gs` + `Index.html`) ที่โรงเรียนใช้ทดลอง

## 1. ปัญหาของระบบเดิม

| ด้าน | ปัญหา | ผล |
|---|---|---|
| ความเร็ว | `getInitialAppData()` โหลดทุกแถวของ 6 ชีตทุกครั้งที่เปิด | ยิ่งใช้นานยิ่งช้า |
| ความเร็ว | ทุกคำสั่งอ่านชีตทั้งแผ่น (`getDataRange`) แล้วเขียนทีละช่อง (`setValue` ×10) | 3–8 วินาทีต่อคำสั่ง |
| ความเร็ว | `LockService.getScriptLock()` ตัวเดียวทั้งระบบ | ผู้ใช้พร้อมกันต้องรอคิว |
| ความเร็ว | PDF ส่งไปกลับเป็น base64 ผ่าน `google.script.run`, Tailwind CDN แปลงในเบราว์เซอร์ | ไฟล์ใหญ่ขึ้น 33% เปิดหน้าช้า |
| ความปลอดภัย | ส่งชีต `Users` (รวม `password`) และ `settings.lineChannelAccessToken` ให้ทุกคน | รหัสผ่านและ token รั่ว |
| ความปลอดภัย | ตรวจสิทธิ์จาก `actorRole` ที่ client ส่งมา, รหัสผ่านค่าเริ่มต้น `1234` เก็บข้อความธรรมดา | ใครก็ทำตัวเป็น ผอ. ได้ |
| ความปลอดภัย | ทุกไฟล์ `ANYONE_WITH_LINK` | หนังสือราชการเปิดได้จากลิงก์ |

## 2. การตัดสินใจ

### แพลตฟอร์ม (Q1, Q2, Q3, Q19)
- เป็นโมดูลใน Next.js app เดียวกับ TSR-SIS (Vercel `sin1`) และ Supabase project เดียวกัน — ค่าใช้จ่าย 0 บาท
- ที่อยู่: **`/sis/saraban`** (app ตั้ง `basePath: "/sis"`) เปิดได้ที่ `gotime.anubantep.ac.th/sis/saraban`
  ถ้าต้องการ `gotime.anubantep.ac.th/saraban` ให้เพิ่ม redirect ใน Caddy ของระบบลงเวลา (นอก repo นี้)
- เริ่มฐานข้อมูลว่าง ไม่ย้ายข้อมูลจากชีตเดิม
- เข้าสู่ระบบด้วย Google อย่างเดียว ใช้ตาราง `staff` เดิม เพิ่ม `saraban_role` และ `work_group` (Q8)
  ครูที่อนุมัติแล้วใน SIS เข้าใช้ได้ทันทีในบทบาท `teacher`

### ข้อมูลและไฟล์ (Q4, Q7, Q9, Q10, Q14, Q15)
- ปริมาณ: หนังสือรับ ~1,500 เล่ม/ปี, PDF ~2MB/เล่ม → ~3GB/ปี
- PDF เก็บใน **Shared Drive ของ Google Workspace for Education** ผ่าน service account
  - เบราว์เซอร์อัปโหลดตรงเข้า Drive ด้วย resumable upload session ที่เซิร์ฟเวอร์เปิดให้ (ไม่ผ่านขีดจำกัด 4.5MB ของ Vercel)
  - ไม่แชร์ไฟล์สาธารณะ เปิดดูผ่าน `/sis/saraban/api/file/:id` ที่ตรวจสิทธิ์ตาม RLS แล้วส่งต่อจาก Drive
  - `Cache-Control: private, max-age=31536000, immutable` — แต่ละเวอร์ชันไม่เปลี่ยน
- ต้นฉบับไม่แก้ไข ทุกการลงนาม/ประทับตราเป็นไฟล์เวอร์ชันใหม่ แสดงล่าสุด ดูย้อนหลังได้
- เลขรับ: ฐานข้อมูลออก เริ่ม 1 ใหม่ทุกปีปฏิทิน พ.ศ. (วันที่ตามเวลาไทย) ธุรการแก้เลขได้ (ห้ามซ้ำ)
- ลายเซ็น: เจ้าของอัปโหลดครั้งเดียว เก็บใน Supabase Storage bucket `signatures` (private) อ่านได้เฉพาะเจ้าของ

### ขั้นตอนงานและสิทธิ์ (Q6, Q16, Q17, Q20)
- บทบาท `director` / `clerk` / `head` / `teacher` บังคับด้วย RLS และ RPC (`security definer` ตรวจบทบาทจาก `auth.uid()` ไม่เชื่อ client)
- ขั้นตอนหนังสือรับ: ธุรการลงรับ + ประทับตรารับ → ธุรการเกษียนเสนอ → ผอ. เลือก 1 ใน 3:
  1. มอบหัวหน้ากลุ่มงาน → หัวหน้ามอบต่อครูใน `work_group` เดียวกัน
  2. มอบครูโดยตรง
  3. ทราบ/จัดเก็บ (ปิดเรื่อง)
- การมองเห็น: ผอ. ธุรการ หัวหน้า เห็นทุกเล่ม; ครูเห็นเล่มที่ได้รับมอบหมาย
  **หนังสือลับ** เห็นเฉพาะ ผอ. ธุรการ และผู้ได้รับมอบหมาย
- QR บนตรารับ → `/sis/saraban/book/:id` ต้องล็อกอินและมีสิทธิ์

### การใช้งาน (Q5, Q11, Q13, Q18, Q22, Q23)
- ธุรการดาวน์โหลด PDF จาก AMSS++/e-office แล้วอัปโหลดเอง ระบบช่วย: เติมหน่วยงานต้นเรื่องที่เคยใช้, เตือนเลขที่หนังสือซ้ำ
- ชั้นความเร็ว ปกติ/ด่วน/ด่วนมาก/ด่วนที่สุด + วันครบกำหนด หน้าแรกเรียงเล่มด่วนและใกล้ครบกำหนดก่อน
- ค้นหาเลขรับ/เลขที่หนังสือ/เรื่อง/หน่วยงานทันทีด้วย `pg_trgm` โหลดทีละ 50 รายการ
- ผอ. เกษียนบนมือถือ ≤ 4 แตะ: เลือกคำสั่งสำเร็จรูป → เลือกผู้รับ → ลงนาม
- LINE OA: **1 ข้อความต่อเล่ม** เข้ากลุ่มครู เมื่อ ผอ. สั่งการ (หนังสือลับไม่แสดงชื่อเรื่อง) token อยู่ใน env ของเซิร์ฟเวอร์เท่านั้น
- แจ้งเตือนรายบุคคลผ่าน Web Push (PWA; iOS ≥ 16.4 ต้องติดตั้งบนหน้าจอโฮม) และเตือนก่อนครบกำหนดวันละครั้ง
- ออฟไลน์: ดูรายการและ PDF ที่เคยเปิดได้ ลงรับ/เกษียน/ลงนามต้องออนไลน์

### การสร้างภาพใน PDF (Q21)
- ตรารับ, คำเกษียน, ลายเซ็น วาดบน canvas ที่ scale 3 (~220 dpi) แล้วฝังเป็น PNG ด้วย pdf-lib ในเบราว์เซอร์
  (pdf-lib + fontkit วางสระ/วรรณยุกต์ไทยผิด) การค้นหาใช้ข้อมูลในฐานข้อมูล

### ความถูกต้องและการกู้คืน (Q24)
- ทุกการกระทำบันทึก `audit_log` ผ่าน `audit_trigger()` เดิม
- "ลบ" = soft delete (`deleted_at`) — ระเบียบสารบรรณเก็บ ≥ 10 ปี
- ตาราง saraban อยู่ใน backup รายสัปดาห์เดิม, bucket `signatures` เพิ่มใน `scripts/backup-storage.mjs`, PDF อยู่ใน Shared Drive

## 3. ลำดับพัฒนา (Q12)
- **เฟส 1**: ทะเบียนรับ เกษียน/สั่งการ มอบหมาย ติดตามการอ่าน (แผน: `docs/superpowers/plans/2026-11-21-esaraban-phase1.md`)
- **เฟส 2**: บันทึกข้อความภายใน (ครูเขียน → ธุรการ → ผอ.)
- **เฟส 3**: ทะเบียนส่ง รายงาน/ส่งออกทะเบียน Excel/PDF

## 4. เกณฑ์รับงาน (Q25)
- หน้าแรก `/sis/saraban` โหลดเสร็จบน 4G ≤ 2 วินาที
- ลงรับ/เกษียน/มอบหมาย ตอบกลับ ≤ 0.5 วินาที (ไม่รวมอัปโหลดไฟล์)
- เปิด PDF ที่เคยเปิดแล้วขึ้นทันที (จาก cache)
- วัดด้วย e2e Playwright ทุกครั้งที่แก้

## 5. การเริ่มใช้ (Q26)
ทดลอง 2 สัปดาห์กับธุรการ + ผอ. (ลงรับ เกษียน มอบหมาย) ใช้ระบบเดิมควบคู่ จากนั้นเปิดให้ครูทุกคน

## 6. สิ่งที่โรงเรียนต้องเตรียม
- ผู้ดูแล Workspace: สร้าง Shared Drive "eSaraban" + service account (Google Cloud) เพิ่มเป็น Content manager
- LINE OA: Channel access token และ group ID ของกลุ่มครู
- VAPID keys สำหรับ Web Push (สร้างด้วย `npx web-push generate-vapid-keys`)
